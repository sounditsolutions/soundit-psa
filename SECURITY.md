# Security Policy

## Reporting a vulnerability

**Please do not open a public issue for a suspected vulnerability.** This tracker is public and its open issues are read as a list of known, unfixed problems — a security report filed here is disclosure, not a report.

Report privately to **«SECURITY CONTACT TBC»**. Include the affected version or commit, what an attacker can do, and the smallest reproduction you have. A proof-of-concept is welcome; it is not required.

## What to expect

Sound PSA is maintained by a small team. We will acknowledge your report, tell you whether we consider it a vulnerability and why, and keep you informed while it is being fixed. If we disagree with your assessment we will say so plainly rather than let the report go quiet.

## Scope

This repository and its default deployment configuration. It does **not** cover any particular hosted instance — if you have found an issue in a specific deployment, contact the operator of that instance.

## Supported versions

This project does not cut releases. **`main` is the supported line**, and fixes land there. If you run a fork or a pinned commit, you are responsible for pulling the fix.

## Disclosure

We ask for a reasonable private window to ship a fix before public disclosure. We will not ask you to stay quiet indefinitely, and we will credit you when the fix lands unless you would rather we did not.
